# DotK 3 Semantic Specification

This is a new language, not a compatibility mode. Files use `.k3`.

## Requirements

- REQ-001: Independent executable, library, build, tests, and documentation; no DotK 2 dependencies.
- REQ-002: let is a non-reassignable binding; var is reassignable. Both are lexical. Assignment to an undeclared name fails. Binding immutability does not imply deep collection immutability.
- REQ-003: Int is signed 64-bit with checked overflow. Float is IEEE double. `/` is floating division, `//` is integer floor division, `%` follows floor division. Mixed comparisons must not round large integers silently. Lossy conversion is explicit.
- REQ-004: Conditions and logical operands must be Bool. `null` is absence, not false.
- REQ-005: Lists `[a, b]`, maps `{"key": value}`, tuples `(a, b)`. Empty `{}` is a map. Scalar negative index is length+index. Slices are start:end:step, end-exclusive, Python-style normalization with separate omitted-bound sentinels. Zero steps fail.
- REQ-006: String is validated UTF-8, indexed by code point. Bytes is distinct (`b"..."`), indexed as Int bytes. Collections.len(String) counts code points; encode/decode are explicit. Grapheme operations require a Unicode library and are a separate implementation task.
- REQ-007: Functions use fn, lexical capture, return, and named arguments `name: value`. Defaults are evaluated on each call. Duplicate positional/named bindings fail. Evaluation order is left-to-right. Variadics have explicit collection binding.
- REQ-008: for loops and generators distinguish yielded null from exhaustion. Generators must be lazy; eager materialization is not an acceptable substitute.
- REQ-009: Immutable structural records, tagged enums and known exhaustive matches. Identity-based classes retain typed let/var fields, named/positional field construction and fresh defaults. Class/record methods bind readonly self across GC/closures/generators. Typed writes and record immutability remain enforced. Traits/defaults use REQ-021, init hooks REQ-022, and static/open inheritance REQ-039/040; advanced traits remain follow-up.
- REQ-010: Optional annotations with runtime checks at dynamic/native boundaries. Resolver rejects undeclared references and illegal writes. A separate static checker provides inference and null-flow diagnostics; it must not be misrepresented by runtime annotation checks alone.
- REQ-011: Structured throw/try/catch and deterministic defer/finally cleanup. Cancellation, budget, and allocation failures are not ordinary catchable script errors.
- REQ-012: Private-by-default module exports, namespace imports and explicit `from ... import name as alias` immutable aliases. Host controls source resolution and native capabilities. No wildcard implicit-global imports.
- REQ-013: Owned source spans, stable diagnostics, formatter/check commands, and shared instruction metadata.
- REQ-014: Host API has isolated instances, controlled output/errors/imports, persistent roots and contextual native calls. Limits are documented, not described as a sandbox.
- REQ-015: One cooperative task model with parent ownership and cancellation; no implicit background thread creation. Blocking native calls cannot be preempted by bytecode budgets.
- REQ-016: A usable CLI with help/version, script/stdin/eval execution, script arguments, a persistent multiline REPL, diagnostics and recovery, and explicit task cleanup on normal shell reset/exit. History, line editing, completion, test-runner and profiling parity are follow-up increments.
- REQ-017: An opt-in source debugger with breakpoints, continue and step-into/over/out, source context, call frames, readonly locals and active-task ancestry/state, including generator/task identity. Paused inspection must remain GC-safe and must not execute script or reenter the VM. AST output alone does not satisfy this requirement.
- REQ-018: A frontend-only stdio language server with versioned unsaved-document diagnostics, UTF-16 positions and document symbols, integrated through an optional trusted-workspace editor client. Advertised capabilities must match implemented behavior; completion/navigation/module inference are follow-up increments.
- REQ-019: Core native services live behind explicit readonly namespaces `System`, `Reflection`, `Collections`, `Text`, `Math` and `Tasks`, not implicit flat function aliases; a shared catalogue supports runtime/checker/member tooling. Explicit imports opt into top-level aliases. Hosts can register qualified native names. Reflection inspection must not invoke methods, and terminal editing/history must use a proven library.
- REQ-020: Callable `List`/`Map` type constructors accept zero or one positional source; shallow copies of typed containers preserve their contracts. List/Tuple/Map/String/Bytes share `.length() -> Int` with code-point String length. Leading function/record/class/trait/enum string docstrings are retained as metadata, readable through Reflection.doc and nonexecuting custom-type LSP hover/member discovery. Triple-quoted strings allow multiline docs.
- REQ-021: Nominal traits require typed synchronous signatures; class/record implements clauses use the same validator as external impl blocks. Failed embedded conformance removes the new type binding. Required names/arity/resolved types/returns must match. Method bodies provide defaults in trait lexical scope; explicit type methods win and competing defaults require an explicit override. Trait identities/default owners are GC-traced and contracts remain pinned. Collections.Sized unifies builtin/class/record length. Generics, associated types, inheritance and variance remain pending.
- REQ-022: Class init hooks run after ordinary field binding/defaults, take no arguments, are synchronous and return Null; GC/cleanup/error behavior is preserved without transactional script rollback. Records support bound methods and trait implementations/defaults without field reassignability or loss of structural data equality. Checker/reflection/debugger/C embedding/LSP tests must cover the combined lifecycle/default/record workflow. Custom constructor argument binding and inheritance remain separate work.

- REQ-023: Map contains/remove use primitive/pinned key contracts, Bool presence/removal results, bounded equality scans and insertion-order-preserving mutation. Eager keys/values snapshots are independent shallow Lists preserving key/value contracts and GC roots, including empty/nominal cases. Runtime/reflection/checker/LSP share method metadata, positional arity and typed snapshot results; host handle tests cover source removal and snapshot lifetime.

- REQ-024: List insertion normalizes negative indexes and validates inclusive insertion bounds/types before mutation; removeAt requires an existing index and returns rooted T without dropping contracts. Extension stages iterable values, validates the whole batch with atomic nested contract attachment, then appends; self-extension is finite and type/iteration/budget failures do not partly append. Source script side effects are not rolled back. Shared reflection/checker/LSP metadata includes positional arity, typed removal results and known source-element checks; host/GC tests cover removed nominal objects.

- REQ-025: Typed List contains/indexOf preserve existing equality, bounded scans and first-match/-1 semantics. List/Map clear preserve contracts and alias identity without changing snapshots. List reverse checks script budgets before mutation. Map get enforces key contracts and returns V? or null without insertion, while indexing remains throwing. Runtime/reflection/checker/LSP share signatures and host/GC tests retain returned objects after clearing. Native work is not a wall-clock preemption guarantee.

- REQ-026: Anonymous fn literals with block/=> bodies support closures, immediate/standalone expressions and normal function parameter/runtime semantics. Direct calls and immutable literal bindings receive known-signature checks. Source extents bound editor parameter scopes; signature hover and typed member discovery remain frontend-only. Generator/default/rest/doc/GC/CLI/REPL and real-client tests verify behavior; dynamic signatures stay runtime-authoritative.

- REQ-027: String contains/startsWith/endsWith match exact UTF-8 Strings; find returns code-point indexes/-1. Split requires nonempty exact separators, preserves empty fields and returns pinned List[String]. Join accepts iterable String elements, roots yielded/results across GC, budgets work and publishes no partial result on failure without rolling back source effects. Shared runtime/checker/reflection/LSP metadata covers literals/bindings/results. Parser grammar matching excludes literal token contents; normalization/graphemes/regex/implicit conversions remain separate work.

- REQ-028: Read-only Files text/bytes/existence/byte-size functions require explicit per-VM host callbacks, deny access by default, validate path arguments and enforce bounded result reads/UTF-8 text. CLI opt-in rooted regular-file adapter rejects absolute/parent/resolved escapes with documented TOCTOU/blocking limitations. Versioned C providers preserve DK3Config ABI, validate borrowed results, support revocation and return BUSY on reentry. Checker/LSP remain nonexecuting and typed; runtime/CLI/host tests cover limits/errors/isolation/GC.

- REQ-029: C handle APIs create/read strict Null/Bool/Float/Bytes and report actual value categories; native callbacks expose scalar/binary getters/returns and live same-VM handle returns. Embedded NUL/empty buffers, finite Float boundaries, GC roots, released/foreign rejection and BUSY reentry must be tested without changing DK3Config or exposing Object pointers.
- REQ-030: Json uses a pinned proven parser with rooted SAX conversion to primitive/List/Map values, exact signed Int64 tokens, finite decimal Floats, duplicate decoded-key rejection and structured syntax/type errors. Compact stringify permits JSON-compatible primitives/arrays/String-key maps, rejects cycles/unsupported/nonfinite values, and enforces depth/byte/step bounds. Checker/LSP remain nonexecuting; host/Files workflows and Unicode/precision/resource boundaries are tested.

- REQ-031: C host APIs construct/traverse owned List/Tuple/Map values, check actual kinds/owners/lifetimes, root extracted children independently and enforce pinned contracts on mutation. Map presence differs from null and traversal order/indexes are live. Publication failures must not expose dangling new handles; Tuple immutability and invalid/foreign/typed failures are tested.
- REQ-032: Callback-local argument/scalar/collection/value/release helpers require the current thread's active DK3Call, reuse checked operations without script reentry and preserve public BUSY behavior. Managed returns receive temporary roots independent of released builders and later allocations. Nested adapters, wrong-thread calls, typed failures, overlapping VMs and a standalone public C example verify ownership.
- REQ-033: Versioned opaque resource descriptors transfer cleanup responsibility only on success, enforce exact tags/VM/live creation-thread access, support idempotent explicit close and same-owner parent dependencies. Release/GC never dispose; separately bounded open state survives collected wrappers. Shutdown preflights threads and closes reverse creation order even after OOM poisoning, without script/reentrant disposal callbacks. Readonly Resource metadata is shared by runtime/reflection/checker/LSP and validated by lifecycle/alias/limit/thread tests.
- REQ-034: Versioned contextual native module descriptors validate identifiers/docs/callbacks/duplicates/collisions and stage a rooted readonly namespace before publication. Failed registration leaves no partial namespace; explicit GC reclaims staged objects. Native modules use existing imports/aliases/reflection docs, preserve legacy registration, and reject undescribed named arguments. No dynamic loader/editor manifest/driver implementation is implied; public C example and allocation rollback tests verify the boundary.
- REQ-035: List map/filter/reduce/any/all/find/findIndex invoke positional callbacks over budgeted rooted shallow snapshots. Predicates require Bool; reduction has an explicit seed and empty identity; queries short-circuit. Filter retains pinned contracts, map outputs can be explicitly annotated, finds preserve nullable element types, and known callbacks receive signature/result checks. GC, source mutation, failure publication, bound methods, budgets, host handles and nonexecuting LSP tests verify the workflow.
- REQ-036: Readonly Random provides per-VM standard-engine seed/float/int/choice/shuffle without global state or implicit OS entropy. Default seed 0 and explicit signed seeds support same-build replay, not cryptography/cross-version sequence guarantees. Integers use strict half-open ranges, fractions stay below 1, sequence choice respects UTF-8/Bytes and shuffle preflights budgets before mutation/draws while preserving contracts. Runtime/checker/LSP/import and procedural example tests cover boundaries/isolation/reproducibility.
- REQ-037: Map compute/computeIfAbsent/computeIfPresent/putIfAbsent/merge use documented null-as-absence/removal semantics, primitive/pinned keys and validated values/results. Managed previous/results survive callback mutation/GC without live iterators; final updates are not applied on callback/result failure, but callback effects are not rolled back. Known callback arity/input/result and V? tooling match runtime behavior; methods are not a concurrency API.
- REQ-038: Trait intersection annotations A & B require every resolved nominal trait in bindings/fields/parameters/returns/collections; (A & B)? is optionally null. Primitive/class/nullable components are rejected. Order and repeated identities preserve contract equivalence; conflicting signatures fail and managed identities remain traced. Checker conformance/member calls and nonexecuting LSP combine known trait metadata without AST mutation; imported unknown types remain runtime-authoritative.
- REQ-039: User classes support static fn and initialized typed static let/var bindings, class-only access, shared owner storage, strict write contracts and detached function/class GC roots. Static functions have no implicit receiver/super, cannot implement instance traits and are excluded from instance constructors/discovery. Runtime/checker/editor/reflection/host tests distinguish member categories.
- REQ-040: Open single class extends supports base-first field construction with declaring lexical contracts/defaults, derived-to-base subtype checks, inherited trait conformance, virtual method lookup and super-method calls on the same receiver. Overrides preserve signatures/category and inherited fields are not redeclared. Selected init runs once with explicit super chaining; hierarchy/owner/proxy roots and a depth bound preserve lifetime safety. REQ-041/042 extend this with custom construction and open collection bases.
- REQ-041: Explicit constructor(...) or parameterized init defines an independent synchronous Null-returning constructor signature with defaults/named/rest arguments and inherited super-init. Defaulted fields initialize first; required fields support checked one-write let initialization and fail on read-before-write, duplicate let writes or incomplete construction. Legacy generated constructors/zero-argument hooks remain compatible; side effects are not transactional.
- REQ-042: Collections exports real open List/Map/Tuple/Set class descriptors shared with literals/host values, and user subclasses retain nominal identity plus native storage. Fields/overrides/super, generic/qualified/alias contracts, indexing/iteration/reflection/GC and C categories work together without finality/freezing or duplicate storage. Native init is construction-only; base copies/slices remain base values and physical bounds stay independent of virtual length.
- REQ-043: Set[T] is mutable, insertion-ordered, iterable and equality-deduplicated, with typed membership/mutation/snapshot/algebra/subset operations and native class subclassing. Contracts and GC preserve referenced values, algebra publishes no partial result on failure, and frontend signatures/result discovery are nonexecuting. Storage is linear, not a hash performance claim; Set is not implicitly JSON-compatible.
- REQ-044: Classes support public-by-default explicit public/protected/private fields, methods, statics and constructors. Access is lexical to declaring class/subclasses, retained across closures/generators/defaults/GC without granting unrelated callbacks ambient rights. Overrides cannot narrow/replace private base members and trait implementations must be public. Runtime/static checks and scope-filtered reflection/printing/completion agree; records remain public structural values and trusted host/native code is not sandboxed.
- REQ-045: Public synchronous instance toString converts top-level script printing/Text.str/REPL values to actual String with GC roots and recursion protection; debugger/reflection/error display remains nonexecuting. Named arithmetic/comparison/unary hooks dispatch on the left receiver with normal contracts, strict Bool comparisons, inheritance and compound result checks. Static known signatures/results and LSP discovery agree without execution; primitives/equality/membership stay unchanged and reflected/equality/hash/index/truthiness overloads are not implied.
- REQ-046: Indexed get/set hooks take key and key/value, require public synchronous methods, enforce Null setters and evaluate compound receiver/key once; static signatures/results and nonexecuting editor discovery agree.
- REQ-047: F-string interpolation parses ordinary scoped expressions, converts rooted values once left-to-right and supports escaped braces, strict malformed replacement errors and nonexecuting checker/LSP metadata.
- REQ-048: Open logical Object root/annotation admits non-null primitive/managed values without boxing or changed equality; Object? and imported/qualified aliases preserve the same contract.
- REQ-049: Error.Kind is a nominal enum carried by caught/user Error records with readonly nested type metadata, explicit category comparison and documented temporary legacy String normalization.
- REQ-050: IO line/output and System timing services use explicit per-runtime callbacks, default-denied input/timing, bounded lines/delays, EOF distinction and IO.Files aliasing. CLI supplies bounded adapters; blocking/raw input/socket/HTTP/port-readiness limits are explicit and verified.
- REQ-051: Explicit Terminal open/close/readKey/isOpen callbacks support default-denied bounded byte reads with zero-timeout nonblocking polls, timeout/EOF distinction and idempotent session lifetime. POSIX CLI termios/poll restoration is verified for explicit close/error/prompt/shutdown paths, without implicit threads/await or signal-kill guarantees. Polling with cooperative tasks and line input remain usable independently of old app architecture; checker/LSP/PTTY tests cover types, lifecycle and progress.
- REQ-052: A playable terminal Tetris model/app implements collision, clockwise rotation/kicks, locking, single/four-line compaction/scoring, timed gravity, preview, pause/drop/game-over/restart and raw-input cleanup. Deterministic model and real PTY controls verify behavior. Explicit CLI step-budget opt-out and per-frame collection support sustained play without claiming modern SRS/hold/bag rules.
- REQ-053: Default-denied Sockets/IO.Sockets capability callbacks expose bounded listen/connect/accept/receive/send/port/close resources with timeout/null versus EOF/empty Bytes, strict inputs and publication/partial-failure cleanup. Opt-in POSIX CLI numeric IPv4 TCP uses nonblocking descriptors, whole sends, deadlines, SIGPIPE protection and bounded separately owned shutdown state. SDK resources remain type-safe and C config ABI unchanged; checker/LSP stay nonexecuting.
- REQ-054: Http/IO.Http uses a pinned proven request/response parser and bounded strict HTTP/1.1 Content-Length framing, Bytes bodies, split-header/body handling, exact byte counts and one overall read deadline. Duplicate/folded/unsupported transfer/interim/version/length/pipelining inputs fail closed. Runnable loopback web/client and multi-client chat examples have real process/readiness/cleanup/binary/UTF-8/interactive tests in canonical make test; TLS/DNS/await/browser UI and production authentication are not implied.
- REQ-055: CLI execution has no step limit by default, with strict explicit --steps N opt-in and zero disablement; long-running execution beyond the old default and finite-budget failure are tested. Embedding defaults remain host-controlled and object/native limits remain independent.
- REQ-056: A shared DotK 3 Pac-Man model ports the legacy maze/cached-neighbor/BFS rules with buffered turns, pellet/power scoring, ghost movement/collisions/cooldowns, lives/respawn, pause/win/game-over/restart/next states and serializable snapshots. A raw terminal app has bounded input, proportional player-following view and cleanup; deterministic model and PTY tests verify behavior.
- REQ-057: A separate readonly-static-asset browser server uses the authoritative DotK game model behind JSON state/action endpoints without changing the API-only server. Responsive canvas, accessible keyboard/touch/icon controls, sound, HUD, connection recovery and local pinned assets work across desktop/mobile. Process/asset/action/malformed-input tests are canonical; live browser pixel/movement/layout checks verify actual rendering without claiming production multiplayer/security or automated editor-host coverage.

## Compatibility Policy

No automatic conversion of old `.k` files. DotK 2 remains built from the parent
Makefile. New syntax examples must be labeled as DotK 3 and tested by its own
runner. A migration tool may be added after the semantics and frontend stabilize.
